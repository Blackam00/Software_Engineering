นี่คือรายการความต้องการ (Requirements) สำหรับระบบ DICMS ที่รวบรวมจากบริบทโปรเจกต์ แบ่งเป็น Functional Requirements (FR) และ Non-functional Requirements (NFR) ครบทั้ง 4 องค์ประกอบตามที่กำหนด

## Functional Requirements (FR)

| ID | ประเภท | Description | Originator | Fit Criteria |
|---|---|---|---|---|

| FR-01 | Functional | นักศึกษาสามารถดูรายการข่าวประกาศของสาขาวิชาได้โดยไม่ต้องล็อกอิน | นักศึกษา | ผู้ใช้เข้าถึงหน้าข่าวประกาศได้ภายใน 2 คลิกจากหน้าแรก และเห็นข่าวล่าสุดเรียงตามวันที่ |

| FR-02 | Functional | นักศึกษาสามารถค้นหา/กรองข่าวประกาศตามคำค้น หมวดหมู่ หรือช่วงวันที่ | นักศึกษา | ระบบแสดงผลการค้นหาที่ตรงกับคำค้นภายใน 3 วินาที และรองรับการกรองอย่างน้อย 2 เงื่อนไข |

| FR-03 | Functional | นักศึกษาสามารถดูรายวิชาทั้งหมดของสาขาพร้อมรายละเอียด (รหัสวิชา ชื่อวิชา หน่วยกิต คำอธิบาย) | นักศึกษา | ทุกรายวิชาที่เปิดสอนในภาคการศึกษาปัจจุบันปรากฏในหน้ารายวิชาครบถ้วนตรงกับข้อมูลที่อาจารย์บันทึกไว้ |

| FR-04 | Functional | นักศึกษาสามารถเข้าถึงลิงก์กลุ่ม LINE ของแต่ละรายวิชาได้จากหน้ารายวิชานั้น | นักศึกษา | ลิงก์ LINE ที่แสดงถูกต้อง 100% และเปิดใช้งานได้ทันทีเมื่อคลิก |

| FR-05 | Functional | นักศึกษาสามารถดูตารางเรียนของตนเอง/ของสาขาตามรายวิชาหรือกลุ่มเรียน | นักศึกษา | ตารางเรียนแสดงวัน เวลา ห้องเรียน และผู้สอนถูกต้องตรงกับข้อมูลที่อาจารย์/เจ้าหน้าที่ป้อน |

| FR-06 | Functional | นักศึกษาสามารถดูปฏิทินการศึกษา (วันเปิด-ปิดภาคเรียน วันสอบ วันสำคัญ) | นักศึกษา | ปฏิทินแสดงเหตุการณ์ครบถ้วนและตรงกับปฏิทินที่มหาวิทยาลัยประกาศ |

| FR-07 | Functional | นักศึกษาสามารถดูข้อมูลอาจารย์ (ชื่อ ตำแหน่ง ช่องทางติดต่อ ห้องพัก เวลาให้คำปรึกษา) | นักศึกษา | ข้อมูลอาจารย์ที่แสดงตรงกับข้อมูลที่อาจารย์อัปเดตล่าสุด |

| FR-08 | Functional | เจ้าหน้าที่สามารถล็อกอินเข้าสู่ระบบด้วยบัญชีที่ได้รับสิทธิ์ | เจ้าหน้าที่ | ผู้ใช้ที่มีบัญชีถูกต้องล็อกอินสำเร็จภายใน 2 ขั้นตอน; บัญชีผิดพลาดถูกปฏิเสธ 100% |

| FR-09 | Functional | เจ้าหน้าที่สามารถสร้าง แก้ไข และลบข่าวประกาศได้ | เจ้าหน้าที่ | การเปลี่ยนแปลงข่าวปรากฏในหน้าเว็บของนักศึกษาภายใน 1 นาทีหลังบันทึก |

| FR-10 | Functional |เจ้าหน้าที่สามารถเพิ่ม/แก้ไข/ลบลิงก์กลุ่ม LINE ของรายวิชาที่รับผิดชอบ | อาจารย์ | ลิงก์ที่แก้ไขแล้วอัปเดตถูกต้องในหน้ารายวิชาทันทีหลังบันทึก |

| FR-11 | Functional | เจ้าหน้าที่สามารถเพิ่ม/แก้ไขข้อมูลรายวิชาและตารางเรียน | เจ้าหน้าที่หลักสูตร | ข้อมูลรายวิชาที่แก้ไขสะท้อนในหน้านักศึกษาโดยไม่มีข้อมูลค้าง (cache) เกิน 5 นาที |

| FR-12 | Functional | ผู้ดูแลระบบ (Admin) สามารถจัดการบัญชีผู้ใช้และกำหนดสิทธิ์ (นักศึกษา/อาจารย์/เจ้าหน้าที่/แอดมิน) | ผู้ดูแลระบบ | แอดมินสามารถสร้าง/ระงับ/กำหนดสิทธิ์บัญชีได้ครบทุกบทบาทที่ระบุในระบบ |

| FR-13 | Functional | ระบบมีช่องค้นหากลาง (Global Search) ให้ค้นหาข่าว รายวิชา เอกสาร และอาจารย์พร้อมกัน | นักศึกษา | ผลการค้นหาครอบคลุมอย่างน้อย 4 หมวดข้อมูล และแสดงผลภายใน 3 วินาที |

| FR-14 | Functional | ระบบแสดงประวัติ/บันทึกการเปลี่ยนแปลงข้อมูลสำคัญ (audit log) สำหรับผู้ดูแลระบบ | ผู้ดูแลระบบ | ทุกการแก้ไข/ลบข้อมูลถูกบันทึก ผู้ใช้ วันเวลา และรายการที่เปลี่ยนแปลง 100% |

## Non-functional Requirements (NFR)

| ID | ประเภท (ชนิด) | Description | Originator | Fit Criteria |
|---|---|---|---|---|
| NFR-01 | Non-functional (Usability) | หน้าเว็บต้องใช้งานง่ายสำหรับนักศึกษาที่ไม่เชี่ยวชาญด้านเทคโนโลยี | นักศึกษา/ผู้พัฒนา | ผู้ใช้ทดสอบ (usability test) อย่างน้อย 80% สามารถหาข้อมูลที่ต้องการได้โดยไม่ต้องขอความช่วยเหลือ |
| NFR-02 | Non-functional (Performance) | หน้าเว็บหลักต้องโหลดเสร็จภายในเวลาที่กำหนดแม้บนอินเทอร์เน็ตความเร็วปานกลาง | ผู้พัฒนา/นักศึกษา | หน้าเว็บโหลดเสร็จสมบูรณ์ภายใน 3 วินาที บนการเชื่อมต่อ 4G มาตรฐาน |
| NFR-03 | Non-functional (Security) | ข้อมูลสำคัญและฟังก์ชันจัดการต้องเข้าถึงได้เฉพาะผู้มีสิทธิ์ที่ผ่านการยืนยันตัวตน | สาขาวิชา/ผู้ดูแลระบบ | ผู้ใช้ที่ไม่มีสิทธิ์ 100% ไม่สามารถเข้าถึงหน้าจัดการข้อมูล (401/403) ได้ |
| NFR-04 | Non-functional (Availability) | ระบบต้องพร้อมใช้งานตลอดช่วงเวลาที่นักศึกษาต้องใช้ข้อมูล (เช่น ช่วงลงทะเบียนเรียน) | สาขาวิชา | Uptime ไม่ต่ำกว่า 99% ต่อเดือน วัดจากบันทึกการมอนิเตอร์ระบบ |
| NFR-05 | Non-functional (Compatibility) | ระบบต้องแสดงผลได้ถูกต้องบนอุปกรณ์และเบราว์เซอร์หลากหลาย | นักศึกษา | แสดงผลถูกต้องบน Chrome, Safari, Edge เวอร์ชันล่าสุด และหน้าจอมือถือ/แท็บเล็ต/เดสก์ท็อป โดยไม่มี layout พัง |
| NFR-06 | Non-functional (Data Integrity) | ข้อมูลที่แสดงต่อนักศึกษาต้องตรงกับข้อมูลล่าสุดที่อาจารย์/เจ้าหน้าที่บันทึกไว้เสมอ | สาขาวิชา | ไม่มีความคลาดเคลื่อนของข้อมูล (ข่าว/ตารางเรียน/ลิงก์) ระหว่างฝั่งจัดการและฝั่งแสดงผลเกิน 5 นาที |
